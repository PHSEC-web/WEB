# PSEC 法律与合规审查记录

更新日期：2026-09-13
适用范围：PSEC 学生研究档案、成员投稿、实验证据、公开附件、学校邮箱登录、阿里云香港服务器/OSS/DirectMail。

> 这不是律师意见，也不能替代学校、监护人或数据保护/伦理审查人员的决定。PSEC 的用户很可能包含未成年人，任何涉及人的研究在上线或开始收集数据前都应由学校指定人员确认。

## 结论摘要

当前最大的风险不是“有没有一页条款”，而是：

1. 未成年人和人类受试者研究可能同时出现；
2. 投稿附件可能含照片、原始数据、文档元数据和可识别信息；
3. 阿里云香港服务器、OSS 和邮件服务意味着需要向用户清楚说明服务商和可能的境外处理；
4. 发布后的附件可能被下载、复制和继续传播；
5. 管理员审核不能被包装成伦理批准、科学验证或学校官方背书。

本轮已在产品中补充隐私政策、使用条款、研究伦理与安全规则、内容与版权规则；投稿和证据补充现在要求学校邮箱登录、版本化确认，并在数据库中记录同意版本。管理员发布前还必须完成公开范围、隐私和版权检查。

## 风险矩阵

| 风险 | 等级 | 现状 | 建议 |
| --- | --- | --- | --- |
| 学校邮箱、姓名、成员 ID、登录 IP 和时间 | 高 | 用于登录、审核和防滥用 | 保持最小化收集；配置保存期限；限制管理员访问；定期清理过期验证码 |
| 未成年人个人信息 | 高 | 用户群体可能包含中学生 | 由学校确认年龄/监护人流程；不要让网站自行声称已取得监护人同意 |
| 人类受试者研究 | 高 | 记录含程序、结果、证据和伦理说明 | 研究开始前完成学校审批、知情同意、去标识化和必要的事后说明 |
| 公开附件、照片和原始数据 | 高 | 发布后可通过受控下载访问 | 默认私有；发布前逐文件检查；不要上传可识别受试者资料；建立下架渠道 |
| 版权、肖像权和第三方材料 | 高 | 成员可上传报告、图片、表格和文档 | 要求作者确认权利来源；保留非独占教育展示许可；处理侵权投诉 |
| 香港服务器、OSS、邮件服务 | 高 | 生产环境使用阿里云服务 | 在隐私政策披露服务商、用途和可能跨境；由学校确认是否需要额外告知/授权 |
| 审核误解为科学或伦理认证 | 中 | 管理员可以 publish/reject | 发布前检查清单；页面和条款明确“不等于批准/验证” |
| 账号、验证码和会话安全 | 中 | 学校邮箱验证码、Cookie/JWT、管理员会话 | 保持 HTTPS；缩短长期会话；持久化限流；轮换密钥；不要把秘密提交 GitHub |
| 数据删除、纠错和审计历史 | 中 | 项目软删除，修订历史可能保留 | 向成员解释公开移除与物理删除的区别；建立人工请求流程和审计保留规则 |
| 恶意上传、滥用和 DDoS | 中 | 有文件类型/大小限制和部分限流 | 在阿里云安全组、WAF/CDN、OSS 私有桶和费用告警层面继续配置；应用层限流不要只依赖单进程内存 |

## 产品侧已落实的控制

- `/privacy`：说明信息类别、用途、公开范围、保存/删除、更正、未成年人、第三方服务和安全边界。
- `/terms`：说明教育用途、用户责任、内容许可、发布后传播风险、管理员处理权限和免责声明。
- `/research-ethics`：说明知情同意、学校审批、未成年人、最小风险、禁止上传内容和经典实验复现限制。
- `/content-policy`：说明版权、肖像、隐私、伪造数据、恶意内容、下架纠错和侵权投诉流程。
- 投稿与实验证据补充均要求登录，并要求确认四个当前条款版本；服务端拒绝缺少或过期版本的请求。
- 新增 `recordConsents`，保存记录/证据对应的隐私、使用条款、研究安全、内容权利版本和成员身份标识。
- 管理员发布前必须确认：公开内容不含不必要个人信息、附件可见性正确，且不把审核表述为伦理或科学认证。

## 上线前仍需人工确认

1. 学校是否把 PSEC 视为学校官方项目；若是，运营主体、投诉联系人、保存期限和学校隐私政策应由学校书面确认。
2. 学校是否要求监护人同意、研究伦理审查、指导老师审批或额外的参与者告知书。
3. 阿里云香港、OSS 和 DirectMail 的实际地域、子处理者、日志保存和跨境安排；将实际配置写入最终隐私告知。
4. `OWNER_EMAIL` 对应的管理员联系人是否稳定可用，并能处理删除、更正、隐私泄露和侵权请求。
5. OSS 是否为私有读写、下载是否使用短期签名 URL、旧对象是否有清理/备份策略。
6. 生产数据库、邮件、OSS、JWT 和管理员密码是否全部在服务器秘密配置中，且没有出现在 Git 历史、截图或日志。

## 建议的运营流程

### 每次发布前

- 检查作者身份和内容来源；
- 检查照片、截图、表格和文档元数据；
- 确认没有姓名、联系方式、学号、健康/心理资料或可识别参与者信息；
- 确认版权、肖像和学校内部材料的许可；
- 确认研究不含未审批的人类受试者风险；
- 仅把确实需要公开的附件设为公开。

### 收到请求或事故时

- 先隐藏公开记录或附件，保留必要的内部审计信息；
- 记录时间、记录标题、请求人和采取的措施，不要在聊天群传播原始敏感文件；
- 对删除、更正、侵权、未成年人或受试者安全请求通知指导老师/学校指定人员；
- 检查 OSS、数据库、邮件和服务器日志，轮换受影响的凭据；
- 需要时向学校和适用法律要求的对象报告。

## 需要查阅的规则方向

最终版本应由学校或律师根据运营主体和用户所在地核对，至少包括：

- 中国个人信息保护、网络安全、数据安全和网络数据相关规则；
- 未成年人保护和未成年人个人信息处理要求；
- 著作权、肖像权、名誉权、隐私权和学校知识产权政策；
- 学校关于人类受试者、问卷、行为实验、照片/视频和未成年人研究的审批制度；
- 阿里云服务器、OSS、DirectMail 的服务条款、隐私政策和数据地域说明。

不要在对外页面写“完全合规”“绝对安全”“已通过伦理审查”或类似绝对结论。
