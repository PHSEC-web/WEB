## 3. 已验证的产品主线

| 验收项 | 验证结果 |
|---|---|
| 匿名调用成员记录创建接口 | 被 `protectedProcedure` 拒绝，返回 `UNAUTHORIZED` |
| 成员记录归属 | 新记录写入 `ownerOpenId`，`/my-records` 仅查询当前登录成员的记录 |
| 审核后的公开展示 | 公开页面从统一 `records` 查询，不读取旧提交表 |
| 版本连续性 | 审计 SQL 未发现 `revisionNo` 首版本非 1 或版本数与最大版本号不一致的记录 |
| 成果追加 | 作者可追加结果、局限、下一问题和附件；写入一条新不可变版本，并将生命周期设为 `completed` |
| 证据包 | `/records/:slug/evidence` 显示记录全文、时间线、公开附件、伦理说明与生成时间；浏览器可打印/保存 PDF |
| 公开附件 | 已发布且公开的记录附件匿名访问返回 307 签名跳转 |
| member-only 附件 | 匿名访问返回 404，不暴露“存在但无权限”的信息 |
| 重复审核 | 记录状态守卫阻止重复同类型审核，返回 `CONFLICT` |

隔离端到端质量验证创建、审核、追加成果并随后清理了临时记录。该验证的结果为：**4 个连续版本、公开附件响应 307、members 附件响应 404、证据包包含 4 个版本**。

## 5. 已知发布注意事项

生产构建成功，但 Vite 报告入口 chunk 为约 638 kB（gzip 约 190 kB）。页面级路由已经采用懒加载；若将来继续优化性能，可在不改变业务行为的前提下进一步拆分共享 UI 与图标依赖。该提示不阻塞当前发布。

成员登录依赖 Manus OAuth 和浏览器 Cookie。Safari 私密浏览、严格阻止 Cookie 的 Firefox 配置或激进的 Brave Shields 可能无法完成 OAuth 登录；公开浏览、公开详情页和公开证据包不受此限制。

## 6. 回滚步骤

1. 保留外部 S0 JSON 备份和旧 `submissions`、`experiments`、`submissionHistory` 表，不执行删除。
2. 如 S5/S6 出现严重问题，恢复到 S4 checkpoint，并将路由切回此前的读取路径。
3. 统一表未被删除，因此可在恢复前导出当前 `records`、`recordRevisions` 和 `attachments` 以保留新产生的成员数据。
4. 仅在单独批准的数据归档周期中，才考虑移除旧表或历史字段。

## 7. 后续建议

后续内容运营可以优先为已完成项目补齐摘要、结果、局限、下一问题和公开报告；再由成员从 **My Records** 追加新的实证材料。对于原始数据，应继续选择 member-only 可见性并在上传前完成脱敏与同意审查。
